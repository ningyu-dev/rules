# 宁雨 · 规范规则库

把给排水规范条文转成可计算、可校验、可追溯的结构化数据。

**这个仓库不包含任何计算代码。** 它是纯数据 + 校验脚本，依赖方向永远是单向的：`core` 消费 `rules`，`rules` 不反向依赖任何代码。一旦规则库开始 import 计算逻辑，就失去了独立验证规则本身正确性的能力。

## 规范原文获取

**本仓库不含规范原文 PDF。** 91 MB 的二进制会让每次 clone 都变重，而规则库本身只有几百 KB。

仓库内保留的是**可校验的证据**：

| 文件 | 作用 |
|---|---|
| `archive/GB50015-2019/SOURCE.md` | 下载 URL、公告号、发布/实施日期、核对状态 |
| `archive/GB50015-2019/SHA256.txt` | PDF 的 SHA-256 |
| `archive/GB50015-2019/announcement.html` | 住建部公告原文（供强条清单机械比对） |
| `archive/GB50015-2019/announcement.sha256` | 公告原文的 SHA-256 |

获取方式：

1. 从 `SOURCE.md` 记录的 URL 下载（住建部公告页附件）
2. 用 `sha256sum` 比对 `SHA256.txt` 确认一致

**文件可信由哈希保证，而非由二进制入库保证。** 任何人下载后都能验证自己拿到的和核对时用的是同一份。

### 该 PDF 是扫描件

179 页，`/Font` = 0，无文字层。条文与附录 F 的公式**无法用脚本提取**，逐条核对只能人工读原页。

`provenance` 因此分两个字段：`page_pdf`（图像页序）与 `page_printed`（规范印刷页码）。扫描时丢失了页面标签，两者不一定一致，以 `page_printed` 为准。

## 为什么不用 RAG

RAG 回答「天沟坡度要求多少」的方式是检索一段原文丢给人。在设计场景这不可用，原因有两点：

1. **校验需要的是可比较的值，不是一段文字。** 判断坡度是否达标需要 `0.005` 这个数，不是「不应小于百分之零点五」这句话。
2. **RAG 输出不可复现。** 同一问题两次检索结果可能不同，而设计文件必须能追责。

RAG 在本项目中的定位降级为：辅助工程师查阅规范原文，**不参与任何计算和判断**。

## 三条硬约束

### 一、版本主键必须是「标准号 + 年份 + 条文号」

规范会换版。GB 50015 从 2003 换到 2019，GB 50014 从 2006 换到 2021。

注意区分**废止**与**修订**：GB 50015-2019 的 31 条强条自 2022-04-01 起被 GB 55020-2021 **废止**，这属于「废止」而非「修订」，**不改变条文数值**。第 5 章（雨水）不在废止清单内，故该章条文原样有效。

系统必须能回答两个问题：

- 用户手上这份图纸，设计时依据的是哪一版？
- 这一版和上一版相比，阈值变了没有？

因此 `rule_id` 的格式由 schema 的正则强制：`^GB\d{5}-\d{4}-(...)$`。不能只用标准名组织条目。

### 二、条文与条文说明必须物理隔离

GB 50015 全文版是「规范正文 + 条文说明」混排的。**条文说明是给编制人员看的解释性内容，设计文件中引用不得。**

`content_type` 字段区分三种内容：

| 值 | 含义 | 能否参与校验 |
|---|---|---|
| `clause` | 规范正文 | 可以 |
| `explanation` | 条文说明 | **禁止** |
| `table` | 附录表格 | 可以 |

这是最容易犯、且一犯就会被工程师当场发现的错误。

### 三、附录表格要表达成可计算的表

GB 50015 附录 F 是屋面溢流设施泄流量计算，附录 G 是重力流系统立管最大设计排水流量。这些是查询表。

结构化之后它不只用来查表，更自动成为校核依据 —— 算出结果立刻能比对附录 G，超了就直接报出超了多少。

## 目录结构

```
rules/
  building_rain/          # 按子系统分目录
    GB50015-2019.json
schema/
  rule.schema.json        # 规则 schema，单一事实来源
scripts/
  validate.py             # 校验脚本
docs/
  DESIGN.md               # 设计决策记录
```

## 强制等级

`mandatory_level` 四级，务必区分：

| 值 | 含义 | 处理方式 |
|---|---|---|
| `strong_clause` | 规范强条 | 必须拦截，不允许用户绕过 |
| `mandatory_general_code` | 强制性通用规范强条 | 必须拦截 |
| `recommended` | 推荐性条文 | 告警，用户可确认后继续 |
| `reference` | 参考值（设计手册取值等） | 仅提示 |
