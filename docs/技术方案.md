# 钢结构厂房屋面雨水设计 · 技术方案

版本 v0.1 ｜ 2026-10-09

---

## 0. 一句话定位

输入用户的建筑图纸，输出屋面雨水系统的斗位布置、管径与立管分区方案，每条结论可回溯到规范条文，用户确认后才出图。

**不做**：屋面排水以外的所有系统（生产废水、洁净区、事故池、消防排水）。后续扩展。

---

## 1. 为什么从这个切口开始

- 系统单一，边界清晰：天沟 → 雨水斗 → 悬吊管 → 立管 → 室外散水
- 变量少：柱网、天沟位置、屋面坡度由结构专业给定，排水专业在给定空间内布管
- 计算密集且可查证：`Q = ψ·q·F`，附录 F/G 直接给出计算图表
- 痛点真实：屋面漏水的主要原因是雨水斗数量不足或位置不当，而非屋面板本身
- 结论可验证：拿现成已审图对照即可判断对错

**战略理由**：这是全链路里唯一能由单人闭环验证的部分。跑通后，"读图 → 规则 → 计算 → 决策 → 出图"的骨架就立起来了。

---

## 2. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 计算内核 | Python 3.11+ | CAD 解析与水力生态全在这里 |
| CAD 解析 | `ezdxf` | 纯 Python，维护活跃，读写 DXF，不依赖本机装 AutoCAD |
| 水力内核 | 本项目自研 + 规范附录表 | 见 §5 说明 |
| 规则库 | JSON（版本化）+ SQLite 索引 | 前后端共享，Python/TS 都能读 |
| 客户端 | TypeScript + React | 出图预览、对话交互、方案对比 |
| 出图 | 自研 → DXF，必要时调 AutoCAD COM | 见 §7 |

**关键判断：不引入 EPANET/SWMM。** 它们是市政管网水力模型，屋面雨水是明渠自由流 + 集中流泄流，物理模型不匹配。屋面雨水的正确做法是按 GB 50015 附录 F/G 的图表查表，这反而更简单也更准。

## 3. 规则库：整个系统的地基

### 3.1 为什么不能做 RAG

RAG 回答"天沟坡度要求多少"的方式是检索一段原文丢给人。这在设计场景不可用，原因是**校验需要的是可比较的值，不是一段文字**。而且 RAG 的输出不可复现——同一问题两次检索结果可能不同，而设计文件必须能追责。

RAG 的定位在本项目中降级为：**辅助工程师查阅规范原文**，不参与任何计算和判断。

### 3.2 数据结构

```json
{
  "rule_id": "GB50015-2019-5.2.11",
  "standard": "GB 50015-2019",
  "standard_year": 2019,
  "clause": "5.2.11",
  "category": "building_rain",
  "scope": "steel_roof_gutter",
  "statement": "金属天沟纵向坡度不应小于 0.5%",
  "rule_type": "numeric_threshold",
  "subject": "gutter_longitudinal_slope",
  "comparator": ">=",
  "value": 0.005,
  "unit": "ratio",
  "mandatory_level": "strong_clause",
  "applies_to": {
    "roof_material": ["metal"],
    "system": ["gravity"]
  },
  "exceptions": [
    {
      "condition": "天沟长度超过 50m 时宜在中部增设排水口",
      "clause_ref": "GB50015-2019-5.2.9"
    }
  ],
  "provenance": {
    "standard_version": "2019 局部修订",
    "page": 87,
    "source_text": "……原文……",
    "extracted_by": "manual",
    "verified_by": null,
    "verified_at": null
  }
}
```

### 3.3 三条硬约束

**（1）版本主键必须是 `标准号 + 年份 + 条文号`，不能只用标准名。**

规范会换版，且是部分条文换版。GB 50015 历经 2003 → 2019 → 局部修订，GB 50014 从 2006 换到 2021。系统必须能回答："这份图纸依据哪一版？这一版和上一版阈值有无变化？"

用户输入需要显式指定标准版本，或由系统按图纸出图年份推断并标注为假设。

**（2）条文与条文说明必须物理隔离。**

GB 50015 全文版是"规范条文 + 条文说明"混排的。条文说明是给编制人员看的解释性内容，**设计文件中引用不得**。规则入库时强制字段：

```json
"content_type": "clause"        // clause | explanation
```

`explanation` 类型禁止参与任何校验逻辑。这是最容易犯、且一犯就会被工程师当场发现的错误。

**（3）附录表格要表达成可计算的表，不是文字。**

GB 50015 附录 F 是屋面溢流设施泄流量计算，附录 G 是重力流系统立管最大设计排水流量。这些是查询表，结构化之后：

```json
{
  "rule_id": "GB50015-2019-appendix-G",
  "rule_type": "lookup_table",
  "subject": "vertical_pipe_max_capacity",
  "axes": {
    "diameter_mm": [50, 75, 100, 125, 150],
    "height_m":   [4, 6, 8, 10, 12, 16, 20]
  },
  "values": [[...], [...]],
  "interpolation": "linear_on_log",
  "mandatory_level": "reference"
}
```

好处不只是查表快，更是**这张表自动成了校核依据**——算出结果立刻能比对附录 G，超了就直接给出超了多少。

### 3.4 规则库的工作量估算

| 分类 | 条文数（估） | 可量化比例 | 备注 |
|---|---|---|---|
| GB 50015 第 5 章 雨水 | 约 40 | 70% | 核心，主要工作量 |
| GB 50015 附录 F/G | 2 | 100% | 表格结构化 |
| GB 50345 屋面工程技术规范 | 约 15 | 40% | 屋面坡度、天沟构造 |
| GB 50014 相关 | 少量 | — | 室外散水衔接 |
| GB 55020 强制性通用规范 | 少量 | — | 强条，必须全收录 |

**约 300–400 条规则，其中可自动校验的约 200 条。** 人工录入，按每天 20 条算，两周到一个月。这是第一阶段的主要工作量，需要找一位给排水工程师配合。

## 4. 输入契约

### 4.1 必须从图纸提取的字段

| 字段 | 用途 | 缺失后果 |
|---|---|---|
| 屋面轮廓（多边形） | 计算汇水面积 | 无法计算，终止 |
| 各分区屋面标高 | 判断排水方向、找低点 | 无法定天沟位置 |
| 屋面坡度与坡向 | 汇水分流 | 斗位排布无依据 |
| 变形缝 / 伸缩缝位置 | 天沟不得跨越（GB 50015 5.2.8） | 需告警，强制生成检查 |
| 柱网轴线 | 落水管避让、立管定位 | 落水管位置需人工确认 |
| 已有天沟位置（如有） | 复用或改造 | 按新建处理，标注假设 |
| 当地暴雨强度 q | 设计流量 | 必须由用户补充，系统不猜 |
| 设计重现期 P | 设计流量 | 必须由用户确认，默认值需标注 |
| 屋面材质 | 径流系数 ψ | 必须询问，不可假设 |

### 4.2 关键设计决定：暴雨强度不做本地计算

q 值依赖当地气象年鉴，数据来源和更新频率都不在项目可控范围内。系统**要求用户输入或选择城市 + 查表**，不做本地推算。原因：算错了会导致整个下游管径全错，且用户无法察觉。

### 4.3 图纸体检：产品的第一个真实功能

输入图纸后，第一件事不是设计，是**明确报出能读到什么、读不到什么**。

```
图纸体检报告
────────────────────────────────
读取成功
  · 屋面轮廓：3 个分区，共 12,400 ㎡
  · 标高：已获取（详见附表）
  · 变形缝：2 处

读取失败，请补充
  ✗ 西北区屋面坡向未标注        → 斗位排布无法继续
  ✗ B 区暴雨强度未提供          → 请选择城市
  ⚠ 已有天沟图层存在但无标高     → 将按新建处理并标注假设
  ⚠ 变形缝 J-2 位置跨越天沟     → 规范不允许，需拆分排水区

可选补充（影响精度，建议提供）
  ○ 屋面材质（影响径流系数 ψ=0.7~1.0）
  ○ 结构专业屋面坡度标注
```

**这个功能比设计能力更能建立信任。** 准确报出"我读不到什么"，工程师立刻知道系统可信；含糊其辞地失败一次，产品就废了。

设计原则：模型允许对缺失项做假设，但**必须标注为假设**，且假设项在最终报告中单独列出。

## 5. 计算流程

每一步都标注对应条文，留痕由此产生。

### Step 1 屋面分区

按坡向划分汇水区。高低跨：GB 50015 要求高跨屋面雨水独立排放，严禁直接排入低跨（GB 50015-2019 5.2.x）。锯齿形厂房同理。

输出：分区列表，每区含面积、坡向、标高范围。
留痕：分区依据的天沟线路径 + 引用的条文号。

### Step 2 设计流量

```
Q = ψ · q · F
```

- ψ 径流系数：金属屋面 0.9（GB 50015 2.1.89 / 5.x）
- q 设计暴雨强度：当地暴雨强度公式，`q = 167A₁(1+C·lgP) / (t+b)^n`，参数需按城市取
- F 汇水面积：按水平投影面积计算；高出屋面的侧墙附加其最大受雨面正投影的一半

 Step 2 输出：每个分区的设计流量 Q (L/s)，附公式与参数来源。

### Step 3 天沟校验

- 净宽 ≥ 200mm（实际建议 600mm，钢结构檩条高度受限需注意）
- 分水线处深度 ≥ 120mm
- 纵向坡度：金属 ≥ 0.5%，混凝土 ≥ 1%
- 长度 > 50m 宜中部增设排水口；> 100m 需组合式
- 天沟水流速度按明渠均匀流公式校核

Step 3 输出：天沟规格建议 + 校验结论。

### Step 4 雨水斗布置

**这是最容易出错的环节，也是本产品价值最高的地方。**

```
单斗排水能力（参考值，需按厂家产品检测报告修正）
  DN75   斗前水深 60mm  →  6–8 L/s
  DN100  斗前水深 60mm  →  约 12 L/s
```

需要的雨水斗数量：
```
n = ceil(Q_total / Q_single)
```

布置约束：
- 斗距 15–24m，跨度大或雨量大取小值
- 斗位靠近天沟低点，避免反坡
- 避开柱位，斗下立管沿柱下行
- 天沟不得流经变形缝和防火墙（GB 50015 5.2.8）
- 高低跨交界需独立设置

Step 4 输出：斗位坐标 + 数量 + 依据。**每一条不满足的约束都要列出违反的条文。**

### Step 5 悬吊管与立管

- 一根悬吊管接雨水斗一般不超过 4 个
- **泄流能力不均**：近斗泄流量是远斗的数十倍（GB 50015 7.3.1），多斗系统必须按最不利斗位计算
- 立管管径按附录 G 校核
- 落水管间距 18–24m，单个排水系统服务面积不超过 5000㎡

Step 5 输出：立管编号、管径、服务的斗位列表。

### Step 6 溢流设施（强制）

GB 50345 要求必须设置溢流设施。工业厂房屋面雨水排水管道工程与溢流设施的总排水能力设计重现期应按生产工艺、重要程度确定；一般工业建筑不宜小于 50 年一遇雨水量。

**溢流设施是强制条文，不能跳过。** 很多实际项目里这一项被漏掉，是重大隐患。

Step 6 输出：溢流口位置与能力校核。

### Step 7 溢流与主系统的独立性

溢流口排水能力应与雨水管道系统独立。这是硬约束——溢流管不能和主立管共用，否则主系统堵塞时溢流失效。

## 6. 留痕机制

这是"自主决策但用户保留最终权力"的技术落点。每条决策都必须可复现、可追责。

```json
{
  "decision_id": "D-0042",
  "stage": "rainhead_placement",
  "summary": "西北区布置 4 个 DN100 雨水斗",
  "derived_from": {
    "inputs": ["分区A.L/s", "Q_single.DN100.Lps", "gut_length_m"],
    "rule_refs": ["GB50015-2019-5.2.9", "GB50015-2019-appendix-G"],
    "rule_vers": ["2019", "2019"],
    "calculation": "n = ceil(45.8 / 12) = 4",
    "assumptions": ["斗前水深按 60mm 取，未按厂家实测修正"]
  },
  "confidence": "computed",
  "requires_human": false,
  "alternatives_considered": [
    {"option": "3 个 DN100", "rejected_because": "单斗能力不足，超设计流量 6.3%"}
  ]
}
```

三个关键字段：

- `rule_refs` — 依据哪些条文，**版本号一并记**
- `assumptions` — 哪些是假设的。**这个字段必须存在，不能省**
- `alternatives_considered` — 考虑过什么、为什么否掉。这是工程师审查时最想看的东西，也是系统可信度的来源

留痕的输出形式：每个方案附一份"决策依据说明"，工程师审查时逐条对照。

## 7. 出图

**第一阶段：出 DXF，不出 DWG。**

`ezdxf` 能直接写 DXF，AutoCAD 打开即可。用户接受 DXF 的理由是：DXF 是只读交换格式，不会破坏原图。工程设计文件最终格式通常是 DWG，但 DXF 作为交付中间格式被广泛接受。

用户若需要 DWG，Windows 下可用 AutoCAD COM 转换——但这要求用户本机装了 AutoCAD，做成可选功能。

**图层组织**（参照实际工程习惯，非规范强制）：

| 图层 | 内容 |
|---|---|
| 雨水斗 | 雨水斗符号 |
| 天沟 | 天沟轮廓与分水线 |
| 悬吊管 | 水平悬吊管 |
| 立管 | 雨水立管与落水管 |
| 溢流 | 溢流口 |
| 标注_管径 | 管径文字 |
| 标注_标高 | 屋面标高 |
| 标注_定位 | 坐标与定位尺寸 |
| 计算书 | 设计参数与校核结论 |

**节点做法单独出详图**，不在本期范围。

## 8. 验证方法

这是项目能否推进的关键。**没有验证手段，一切都是自嗨。**

### 8.1 静态验证：与现成图纸对照

收集 10–20 份已通过施工图审查的钢结构厂房屋面雨水图纸，人工标注"标准答案"，跑系统对照。

**指标**：
- 斗位数量偏差
- 管径偏差
- 立管分区偏差
- 是否漏检规范约束

第一阶段目标：斗位和管径完全一致的图纸达到 60% 以上。**不要追求 100%**——工程师的手工方案本身就不唯一，能对上大方向就有价值。

### 8.2 手算对照

挑 2–3 个案例，完整手算一遍，与系统结果逐步比对。这能发现公式实现层面的错误，成本低，必做。

### 8.3 反向验证：找反例

主动构造违反规范的输入，检查系统是否正确报错。**这个能力比"算对"更重要**——产品要在用户出错时拦住他。

### 8.4 成功指标

用唯一有意义的指标：

> **系统方案被工程师直接采纳的比例，以及需要修改的幅度。**

不是"任务成功率"，不是"规则覆盖率"。前者衡量系统是否真的有用，后者只衡量工作量。

## 9. 分期

### Phase 0：规则库地基（2–4 周）

**这件事必须最先做，且是最容易被低估的部分。**

- 确定纳入范围的标准清单
- 录入 GB 50015 第 5 章 + 附录 F/G
- 附录表格结构化
- 规范 PDF 原文归档，作为 `provenance` 校验依据

**需要一位给排水工程师全程配合。** 这是唯一无法靠工程直觉绕过的依赖，越早启动越好。

**里程碑**：规则库覆盖屋面雨水全部强条，能对一份手工计算表做完整校核。

### Phase 1：最小闭环（4–6 周）

- 图纸导入 + 几何提取（DXF 输入）
- 图纸体检
- Step 1–5 计算链路
- 决策依据说明生成
- 手工校核表输出

**里程碑**：给一份真实 DWG，用户能得到一份带完整留痕的计算书，人工核对无重大错误。

**这一阶段不做**：对话交互、出图、虹吸分支。

### Phase 2：出图与交互（4–6 周）

- DXF 出图
- TypeScript 客户端
- 对话式交互（自然语言 → 调用引擎接口）
- 方案对比

**里程碑**：工程师可以完整用它做一版屋面雨水方案。

### Phase 3：扩展（长期）

- 虹吸分支（输出厂家选型清单）
- 扩展到其他屋面形式（混凝土屋面、坡屋面）
- 扩展到排水其他系统

---

## 10. 明确不做的事

写下来避免范围蔓延：

- ❌ 不做结构专业的事（荷载、构件验算）
- ❌ 不做暖通、建筑给水、生活污水系统
- ❌ 不做虹吸水力计算（转厂家选型）
- ❌ 不出 DWG 原生格式（可选调 AutoCAD 转换）
- ❌ 不做节点详图
- ❌ 不自动出图给施工（必须用户确认）
- ❌ 不用 RAG 参与任何计算和判断（仅作规范查阅辅助）

## 11. 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 找不到愿意配合的工程师 | Phase 0 无法启动，项目停摆 | 这是第一优先级要解决的，早于写代码 |
| 规范解读有歧义 | 规则库返工 | 每条规则双人复核，记录判读依据 |
| 图纸质量差导致读图失败 | 用户体验崩塌 | 图纸体检功能前置，把失败变成明确告警 |
| 版本管理混乱 | 出错难追责 | 从第一天就做版本主键 |
| 与现有 CAD 软件竞争 | 定位模糊 | 不做通用 CAD，只做排水专业插件式能力 |
| 范围蔓延 | 什么都做，什么都不成 | 用 §10 作为边界，反复守住 |

## 12. 待确认事项

1. **目标用户是谁**——设计院的给排水工程师？还是施工单位的深化设计？还是业主？不同用户对"自主决策"的接受度完全不同。施工方接受度更高，设计师最抵触别人替他决策。

2. **输出格式**——DXF 是否够用？用户实际交付需要什么格式？需要 DWG 吗？

3. **是否需要三维**——屋面排水做二维平面图够用吗？三维深化是另一个量级。

4. **前期投入**——规则库录入需要工程师参与，是付费合作还是自己想办法？这决定项目的启动条件。
