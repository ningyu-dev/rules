# OCR 读页流程（扫描版规范）

> 2026-11-01 起启用。目的：把扫描版规范变成**可定位、可检索的文本**，用于找条文页码与初读；
> **不用于代替人工核对。** 凡与页面图像冲突，以图像为准。

## 一、为什么做

- 项目归档的 PDF 多数是扫描件（`/Font`=0、无文字层）：GB 50015-2019、GB 50014-2021、GB 51022-2015、
  GB 50345-2012、GB 55020 / 55030 / 55001 / 55003 / 55006 / 55026 / 55027 等都有图像页。
- 此前环境「无任何 PDF/OCR 工具」，导致 42 条 `page: 0`、`5.2.35 单斗内排水` 等条目无法定位。
- 2026-11-01 用户定调：**扫描件可以用 OCR 相关 AI**，且不买正式出版文本（缺的正文优先找网上公开分享件，标「转载」）。
- 本机没有 poppler / tesseract，但 macOS 自带 **PDFKit + Vision**（端侧识别、无需联网、无需安装）。
  已封装为 `scripts/ocr_vision.swift` + `scripts/ocr_pages.py`。

## 二、工具与用法

```bash
# 单本整本 OCR（首次运行会 swiftc 编译到 tmp/bin/ocr_vision，tmp/ 已 gitignore）
python3 scripts/ocr_pages.py archive/GB55020-2021/GB55020-2021.pdf tmp/ocr/text/GB55020-2021 1-28

# 只识别指定页
python3 scripts/ocr_pages.py archive/GB50057-2010/GB50057-2010.pdf tmp/ocr/one 16-17

# 产出：<输出目录>/pages.jsonl（每页文本行+坐标）、page_NNN.txt（纯文本）
```

渲染单页为 PNG（核对用）：

```bash
python3 - <<'PY'
from Quartz import PDFDocument
from Foundation import NSURL
# 用法见 tmp/pdfkit/render.py；pdfkit 脚本属临时工具，口径以本文件为准
PY
```

## 三、口径（必须遵守）

1. **OCR 只做定位与初读。** 可用于：找条文在 PDF 哪一页、回填 `provenance.page`、全文检索、抽取表格候选。
2. **OCR 不作为条文数值依据。** 数值、表格、公式必须对照页面图像逐条核对；`verified_by` 仍须工程师签字。
3. `extracted_by` 语义不变（条文录入方式）；「页码来自 OCR 定位」记录在 `核对任务清单.md`，不写进
   `extracted_by`——否则会把「录入方式」与「定位方式」混成一件。
4. **OCR 定位必须被验证**（同 D-010 思路：手段本身要证明它在工作）：
   - 用已知页码的 GB 50015-2019 自检：32 条中 30 条（另 2 条为附录 F/G，单独处理）OCR 定位页
     与既有 `provenance.page` **100% 一致**（2026-11-01 实测）；
   - 每本回填后抽 2–3 条渲染页面读图确认页码（2026-11-01 已抽 GB55020 / GB55030 / GB50014 / GB51022）。
5. **页脚偏移必须实核，不能猜**：各标准 PDF 页与印刷页有固定偏移，但前附件（公告/前言/目录）可能单独编号。
   2026-11-01 实测正文偏移：

   | 标准 | PDF 页 → 印刷页 |
   |---|---|
   | GB 50015-2019 | 印刷 = PDF − 8 |
   | GB 50014-2021 | 印刷 = PDF − 8 |
   | GB 51022-2015 | 印刷 = PDF − 8 |
   | GB 55020-2021 | 印刷 = PDF − 4 |
   | GB 55030-2022 | 印刷 = PDF − 4 |

## 四、2026-11-01 实测

- 5 本共 **499 页**：GB55020 28 页 / GB55030 40 / GB50014 117 / GB51022 135 / GB50015 179；
  并行约 90 秒（Apple M4，220 dpi，端侧）。
- 页码回填 **36 条**：GB50014 13 条（印刷 13–28）、GB51022 11 条（44–92）、GB55020 8 条（10–11）、
  GB55030 4 条（16）；另有 44 条原本已填（GB50015 32 + GB50345 12）。
- 全库 86 条中 **80 条有页码**；剩 6 条为工程经验条目（无规范出处，`page: 0` 是设计如此）。
- 抽页核验（渲染原页读图）：GB55020 PDF p14 → 印刷 10（4.5.1–4.5.6）、
  GB55030 p20 → 印刷 16（4.4.3–4.4.5）、GB50014 p30 → 印刷 22（表 5.2.10）、GB51022 p99 → 印刷 91（11.1.1）。

## 五、局限（必须知道）

- OCR 会把条号断行或插空格（如 `4.5. 12`）；定位脚本已做宽松匹配，人工复核仍以图像为准。
- 水印、页眉会混入文本；表格与公式识别不可靠——**附录 F 的五个公式在官方原文里就是图像**，
  OCR 读不出代数式，这仍是 P1-1 保留的限制。
- 高精度升级（可选，不在当前依赖内）：**MinerU**（PDF→Markdown/JSON，表格转 HTML、公式转 LaTeX，
  CPU 可跑）；**PaddleOCR-VL**（文档解析 SOTA，需 PaddlePaddle 3.2.1，macOS 建议 Docker）。
  若引入，识别结果同样只作初读，仍须逐条对照图像复核，不得直接标「已核对」。
