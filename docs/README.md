# 文档地图

> 这个目录下的文档怎么读、哪些该入库、新文档放哪。
> **新增或改名文档时先更新本页。** 本页只是索引，不承载结论。

## 0. 先记三条判据

1. **文档分两类：结论 / 推导过程。** 结论（决策、规划、证据链、任务清单）入库；一次性判断与流水账只留本地（`.gitignore` 有规则、CI 有断言）。**判据不是「文件叫什么」，是「它是结论还是推导过程」。**
2. **汇总数字必须写口径**（D-009）。本页出现的数字都注明了怎么数出来的；答不上口径的数字不要写进文档。
3. **`docs/` 下文件名不要含「核对」二字**。`scripts/verify_checklist.py` 用 `docs/*核对*.md` glob 找核对清单，多于一个会直接报错。

## 3. 新会话开工顺序

1. `../README.md`：仓库总入口，含当前状态与待办。
2. 本页：知道去哪找。
3. `待决策事项.md`：有什么卡着。
4. 按任务分线：
   - 规则 / 录入 → `规范依据规划.md` + `核对任务清单.md` + 对应读页记录
   - 信源 / 现行性 → `信源与更新机制.md` + `../sources/standards.json`
   - 归档 / 正文 → `../archive/<标准号>/SOURCE.md` + `../scripts/README.md`
5. 开工前跑一遍硬门禁（与 CI 同款）：

```bash
python scripts/verify_checklist.py          # 清单 86 行 ↔ 草稿 86 条
python scripts/validate.py --drafts-only    # schema（草稿）
python scripts/check_sources.py --structure-only
python scripts/check_strong_clause.py       # 引用已废止强条（E100~E102）
python scripts/build_abolished_list.py      # 废止清单自洽（CI 不加 --apply）
python scripts/audit_archive.py             # 归档台账 + 公告哈希一致性
```

## 5. 维护规则

- **新增文档**：先判类（结论 / 证据链 / 任务清单 / 过程记录），在本页「文档清单」登记；过程记录不要新增 `.gitignore` 之外的新类别。
- **改名**：换名要同步本页与所有引用（先 `grep` 旧名），并注意 `verify_checklist.py` 的 `*核对*.md` glob。
- **过期**：数字过期用「口径 + 新值」覆盖并写明复核日期；历史记录不追改，在末尾加「更正」小节。
- **证据链不得加入 ignore**：`*-读页记录.md`、`核对任务清单.md` 被 CI 断言必须入库。

## 6. 重复内容与单一事实来源
